# 方块搭子 V2.1 · 三个核心模块定稿

> 本文是 `docs/v2-design.md` 中“首轮三个核心模块”的实现修订说明。后续渐进式模块（队伍规模、存档周期、语音、约局、资源、角色、学习等）不在本文范围内。

## 1. 核心模块的产品目标

三个核心模块只负责让玩家用较低负担建立“足够开始匹配”的基础画像：

1. 玩法兴趣 + 最近最想玩
2. 一周上线时间
3. 多人游戏核心习惯

完成这三个模块后，**基础画像完成度 = 100%**，可以生成正式 Top 3。

这和候选人卡片上的“了解程度 / Confidence”是两个概念：

- 基础画像完成度：只看玩家是否完成三个必需模块。
- 候选人了解程度：看双方共同已知的匹配数据覆盖量；未来加入渐进式问题后会继续提升。

## 2. 模块一：玩法兴趣

保留 0–4 五档评分，不要求全部玩法都回答。

页面必须醒目提示：

> 不用全部填写。挑 2～5 个你有明显感觉的玩法评分就够了；其他直接留空。留空 = 还不了解你，不等于不喜欢。

统一问题：

> 如果社团里有人喊你玩这个，你通常会？

评分：

- 0：基本不去
- 1：多半不去
- 2：看情况
- 3：大多会去
- 4：很想加入
- 未回答：`null`

短期意图只保留一个概念：**🔥 最近最想玩**，最多标记 2 项。

## 3. 模块二：一周上线时间

时间热力图为 **7 天 × 4 时间段**：

- 上午：约 08:00–12:00
- 下午：约 12:00–18:00
- 晚上：约 18:00–22:00
- 深夜：约 22:00 以后

每格：

- 未设置：未知
- 1：偶尔
- 2：经常

继续保留快捷填写和 `availabilityRandomness`。新增“上午”不会改变 JSON 数据结构，只增加新的时间槽 key，例如 `sat_morning`。

服务端匹配直接按任意时间槽计算真实重合，因此上午与原有时间段享有相同匹配能力。

## 4. 模块三：多人游戏核心习惯

核心轴仍为：

1. 推进强度
2. 行动同步
3. 分工程度

每轴保留五档语义选择。

**取消用户可见的“其实两边我都能适应”复选框。**

原因：它与中间档“都可以”语义重复，且会增加理解和操作负担。

统一规则：

- `ideal = 2`（都可以）→ `tolerance = 2`
- 其他核心档位 → `tolerance = 1`

因此“都可以”本身就代表高适应性，不再让玩家单独管理 tolerance。

## 5. 基础画像进度

顶部不再展示“了解你 X%”作为全局问卷完成度，而展示：

> **基础画像完成度**

进度规则：

- 兴趣模块未完成：0%
- 兴趣模块完成：33%
- 时间模块完成：67%
- 三个游戏习惯回答完成：100%
- 完成页保持 100%

候选人卡片上的 `Confidence` 保持独立，不要求在三个核心模块完成后达到 100%。

## 6. 与后续渐进式模块的关系

三个核心模块达到 100% 不代表系统已经知道玩家的所有偏好。

后续仍计划通过“让推荐更准”的可选流程逐步采集：

- 队伍规模 / 存档周期
- 语音 / 约局方式
- 资源共享
- 队伍角色
- 教学 / 查资料习惯

这些信息用于继续提高候选人 `Confidence` 和排序稳定性，但不会阻塞首次 Top 3。
